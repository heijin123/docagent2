## 二、明确不吸收（4 项，含原因）

| doc-agent 的做法 | 不吸收原因 |
|---|---|
| 业务失败返回 HTTP 200 + `status=failed` | 本项目契约已采用标准状态码 + 统一错误体（§1.5），语义更严格，前端区分"解析失败/服务不可用"更直接；两种哲学不兼容，不折中 |
| 每文档一条 LangGraph 摄取图 | 本项目入库编排走异步任务队列（F1.5 + 契约 §4.8），失败隔离与断点续跑已由 DocRegistry + `chunk_exists` 覆盖；摄取是确定性流水线，是否上 LangGraph 是形态偏好，不为形态改架构。将来做文档粒度并行时可再评估 Send |
| `image_id = {doc_stem}-{md5前10}` 直接拼文件系统路径 | 思想吸收（内容幂等），实现细节交本项目 F1.10 自行定义；登记表复用 F1.8 的 DocRegistry 体系而非另建 sqlite schema |
| 转录文本追加块流尾部（v2 语义） | 被版本化软更新（F1.7）整体取代：本项目内容变更即 version+1 全量新插，不存在"老块 id 不能动"的约束 |

## 三、7.1 元数据变更摘要（v1.2）

```jsonc
// 文档级（新增 2 个）
"doc_date": "2025-03-01",   // 文件名解析，期次溯源（F2.9，可选）
"doc_year": 2025,           // 年份 int，供 where 过滤（F2.9）

// chunk 级（新增 1 个）
"image_ids": "img_a1-3f2c1b", // 图片 ID 逗号串（Chroma 只收标量），召回回填（F1.10）
```

注意：`effective_time`（现行性，F2.8）与 `doc_year`（期次，F2.9）**语义不同、并存不混用**。

## 四、设计守则对照（doc-agent 八条 → 本项目）

| doc-agent 守则 | 本项目对应 |
|---|---|
| 不过度设计，只写当前需求的最小结构 | 开发计划按里程碑推进，P1 项（rerank、任务查询）有明确开关与优先级 |
