# 多轮对话评估（step 0）— 2026-09-14

> **一句话结论**：多轮的 history 代价**不大**（1 轮历史 ≈ +90~310 tok），但**多轮一定会多烧一跳 rewrite**——
> 5/5 末轮都走了 LLM 改写，跳过率 **0%**，其中 1 条（完整独立问题）的改写结果**与原文逐字相同**，
> 是 100% 纯浪费。修 `should_skip_rewrite` 之前，任何多轮对话都比单轮贵一跳。

- 模型：`qwen3.8-flash`｜provider：dashscope（真实向量）｜thread 盐值：`20260914-163353`
- 规模：**5 条 / 10 轮真实 LLM / 25 次调用**；prompt 26,442 tok + completion 1,967 tok；成本 **¥0.0265**；单轮均 2,840.9 tok
- 机器可读：`data/reports/eval_multiturn_latest.json`｜题集：`data/golden/qa_golden_multiturn.json`
- 脚本：`scripts/eval_multiturn.py`

## 1. 为什么要单独一套（而不是并进现有 golden）

现有单轮集用**原始 query** 算 recall@5。多轮末轮多是指代/省略句（「那市内交通补贴呢？」），
原始 query 本身不含可检索内容——混进去会让 recall@5 因**口径错误**而暴跌，那不是真实退化。

因此多轮集**分开存放、分开加载**，且检索/可回查口径一律基于**改写后的 effective query**
（从 `reply.notes` 提取），并由专用脚本逐轮留档。`app/eval/golden.py` 新增
`MultiTurnCase` + `load_multiturn_golden`，校验口径与单轮一致（缺字段 / 重复 id / 锚句 <6 字即抛错，
且额外要求 `len(turns) >= 2`）。

字段：`turns`（用户轮列表，**末轮**为被评估对象）、`category`、`expected_doc`、`anchor`。
assistant 轮**不入 golden**——它由真实链路生成，这正是多轮测试的意义。

## 3. 结论一：`should_skip_rewrite` 的跳过率是 0%

| id | category | 期望 | 实际 | 改写结果 |
|---|---|---|---|---|
| m001 | anaphora | llm | llm ✓ | 2026版差旅住宿标准是什么时候开始执行的？ |
| m002 | ellipsis | llm | llm ✓ | 部门经理出差住酒店一天最多能报多少钱？ |
| m003 | independent | **skip** | **llm ✗** | 园区停车月卡多少钱？（**与原文逐字相同 = 空转**） |
| m004 | anaphora | llm | llm ✓ | 年假没用完的部分怎么处理？ |
| m005 | ellipsis | llm | llm ✓ | 差旅报销的市内交通补贴标准是多少？ |

根因是 `prompts.should_skip_rewrite`（`app/agent/prompts.py:71`）的第一道判据：

```python
if history and history.strip():
    return False      # 只要有历史，就一律重写
```

它排在词表判据**之前**，于是**词表根本没机会参与判定**。后果有两层：

1. **该跳的跳不掉**：m003 的 query 完整、无指代、与上文无关，模型自己也认为无需改写
   （改写输出与输入逐字相同），却仍被强制跑了一次 LLM。这一跳 **100% 浪费**。
2. **该验的没验到**：连"无指代词省略句"这类**最需要 rewrite** 的情况，也是靠"有历史"这条
   粗糙规则兜住的，而不是靠真正的语义判据。修规则时若只加"短句 + 无实体"启发式而不做验证，
   m002 这类句子就是第一个被误跳的回归点——**这正是把它放进样本集的原因**。

## 4. 结论二：多轮开销的构造式分解（零 LLM 成本）

`Δprompt = 末轮 prompt − 首轮 prompt` **不能**当 history 成本用——它被 evidence 体量波动淹没：

| id | hop1→hop2 | prompt1 | prompt2 | Δprompt | Δ% |
|---|---|---|---|---|---|
| m001 | 2→3 | 2521 | 3069 | +548 | +21.7% |
| m002 | 2→3 | 2418 | 2374 | **−44** | **−1.8%** |
| m003 | 2→3 | 2522 | 3020 | +498 | +19.7% |
| m004 | 2→3 | 2337 | 3144 | +807 | +34.5% |
| m005 | 2→3 | 2330 | 2707 | +377 | +16.2% |

m002 的 hop 数也涨了，Δprompt 却是**负的**（末轮检索到的证据更少）。所以改用
**「同题、同证据、只切换 history 段」**的构造式测量（`prompts.answer_prompt` /
`rewrite_prompt` 各构两版，只变 history 参数），把增量精确分离：

| id | 本轮 history | → answer 注入 | → rewrite 注入 | rewrite 整跳 | history 净增 |
|---|---|---|---|---|---|
| m001 | 248 字 | +248 | +248 | 286 字 | 496 字 ≈ **310 tok** |
| m002 | 100 字 | +100 | +100 | 134 字 | 200 字 ≈ 125 tok |
| m003 | 249 字 | +249 | +249 | 282 字 | 498 字 ≈ 311 tok |
| m004 | 71 字 | +71 | +71 | 107 字 | 142 字 ≈ 89 tok |
| m005 | 193 字 | +193 | +193 | 225 字 | 386 字 ≈ 241 tok |

三条要点：

1. **history 被注入两次**（rewrite 一跳 + answer 一跳），与 `render_history` 的调用点一致；
   `verify` **不注入**（刻意设计），增量为 0。两处增量逐字相等（同一段文本直接拼接），可作自检通过。
2. **当前 1 轮历史的净代价很小**（89~311 tok）：因为助手回答已被限长到 ≤200 字，
   且 `[:300]` 截断基本不触发。多轮本身的边际成本**不吓人**。
3. **外推上限才是雷**：窗口 `10 轮 × 2 条 × 300 字 = 6,000 字/次注入`，两次注入 ≈ **7,500 tok/问**
   ≈ 现单问 prompt 的 2.5 倍。单轮评估里 history 恒为空，这个成本**一个数字都测不到**。

> 折算比 1.6 chars/token，取自本轮 `llm_call` 日志的 5 组 `prompt_chars/prompt_tokens` 实测
> （1.568~1.660，同内容自校准）。

## 5. 结论三：多轮下答案质量没有崩（但门槛偏低）

- **引用可回查 5/5 = 1.000**；**锚句命中 5/5 = 1.000**；末轮延迟 p50 5,782ms / max 6,673ms。
- 4 条需要补全的末轮**全部改写正确**，且答案落在现行版：
  - m002「部门经理的标准是多少？」→ 正确补全为「部门经理出差住酒店一天最多能报多少钱？」
    → 答 **1100/天（v2）**，没串到 v1 的 700/天；
  - m005 → 答 **120/天（v2）**，没串到 v1 的 80/天；
  - m005 的答案还正确区分了「住宿 vs 市内交通」两个不同科目。
- **但门槛偏低，不宜过度乐观**：m001 / m005 的期望块是**同一个 chunk**
  （`doc_5a85f5b0b6da_0002_00003` 同时含"市内交通/审批权限/时限/新旧衔接"），
  该文档 top-5 几乎必然带回它 → "可回查"很容易达成。语料小 + chunk 粒度较粗，
  5 条样本不足以外推多轮质量结论。
- 小瑕疵：md 来源的引用标记显示为「第 0 页」（`page_num=0`），多轮下同样出现，属既有问题。

## 8. `should_skip_rewrite` 白名单重构（2026-09-14 落地 + 实测）

### 8.1 问题：判据与本句内容解耦

旧实现 `prompts.should_skip_rewrite` 是：

```python
if retry_count > 0: return False
if history and history.strip(): return False   # ← 前置一票否决：有历史 → 必改写
...
return not any(h in q for h in _PRONOMINAL_HINTS)   # ← 词表被挡在门外
```

「有历史」被放在**一票否决位**，于是 `_PRONOMINAL_HINTS` 词表**只对首轮生效**：
第 N（N≥2）轮无论本句是完整独立问题、还是全靠上文补全的省略句，一律改写。
语义上 rewrite 的作用是「消解本句对上下文的依赖」，**有无历史只是消解的前提，
不是触发理由**。直接后果就是 m003（完整独立问题）被强制改写，且改写结果与原句
**逐字相同**——纯空转，白烧一跳。

### 8.2 新判据：白名单（默认改写，只证明「自足」才跳过）

```
自足 ⟺ 无回指  且  长度 > 8  且  非「…的 + 通用中心词」  且  含主题锚点
自足              → 跳过
不自足 + 有上文    → 改写（有东西可消解）
不自足 + 无上文    → 跳过（无消解对象，硬改只会让模型编一个主题）
```

「默认改写」是刻意的：判错方向不对称——**多改只浪费一跳，漏消解会让检索拿到
一句读不懂的话**。锚点词表**不手写**，由 `app/agent/anchors.py::build_vocab`
从语料派生（文档中文标题词 + 标题 2 字片段 + 正文词，过词性/通用中心词/功能词/
首尾功能字四道滤，产出 1,580 词 / 38 文档），`ingest` 后自动重建。

### 8.3 离线校验（纯规则、零 LLM：`scripts/replay_skip_rewrite.py`）

| 判据 | golden 多轮 5 条 | 人工探针 12 条 |
|---|---|---|
| 旧 | 4/5（✗ m003 空转） | — |
| **新（白名单）** | **5/5** | **12/12** |

- 短句下限阈值取 4/5/6/7/8/9/10 做敏感性：**5~8 区间结果完全一致**（golden 5/5、
  探针 12/12）→ 结论不依赖调参。
- 单轮 55 条里「自足」45 条（81.8%）——即多轮中这些题可省掉改写跳。
- 已知保守偏差（设计取舍，非缺陷）：7~8 字短问被判需改写；「…的+上限」结构被否决。

### 8.4 真实链路实测（同 5 条多轮样本，冷启动口径）

| 运行 | 判据 | LLM 调用 | 成本 | m003 末轮 | m002 末轮 | 可回查/锚句 |
|---|---|---|---|---|---|---|
| 基线 | 旧 | 25 | ¥0.0265 | 3 次 + **改写空转** | 3 次 | 5/5 · 5/5 |
| run1 | 新 | 27 | ¥0.0290 | **2 次（skip）** | 6 次（verify 抖动） | 5/5 · 5/5 |
| run2 | 新 | **24** | **¥0.0252** | **2 次（skip）** | 3 次 | 5/5 · 5/5 |

- **`skip_rate` 0/5 → 1/5，`identity_rewrites` 1 → 0**：m003 空转消失，末轮省一跳。
- **质量三项全保持**：5/5 可回查、5/5 锚句命中，四条需补全的末轮改写结果与基线一致
  （m002→1100/天 v2、m005→120/天 v2 均未串版本）。
- **run1 的 m002 6 次调用是 verify 抖动，不是回归**：run2 同题同答案、0 重试、3 次调用。
  印证了此前记录过的「verify 有随机性（temperature=0.2）」。
- 本样本集只有 1 条独立追问，故净收益仅 1 跳；真实多轮会话里独立追问占比越高收益越大。
